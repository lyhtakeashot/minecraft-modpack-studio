# minecraft-modpack-studio

Minecraft 整合包工作室（桌面版）。

**一句话**：同一件事，你可以**点界面**做，也可以**写代码**做；可以**从零攒一个新包**，也可以**改别人做好的包**。

这是一个**独立的桌面软件**（Electron 应用），双击就能用，不需要装任何插件、不需要先起一个别的宿主程序。

---

这四条是判断「有没有写偏」的标准。任何功能，只要不服务于这四条之一，就不该进这个项目。

## 一条设计原则：两种做法，一套底层

这是整个项目最重要的约定。

同一个改动，比如「把齿轮改成 2 个铁锭合成」，应该有**两条路**通向同一个结果：

```
点界面改 ─┐
          ├─→ 同一套底层操作 → 同一个文件改动 → 同一份备份
写代码改 ─┘
```

**为什么必须这样**：

- 界面做不了的复杂改动，代码能做（批量、条件、循环）
- 代码写烦了的重复改动，界面能点（可视化、看得见）
- 两条路走的是同一套逻辑，所以**界面里看到的一定和代码改出来的一样**，不会出现「界面显示改了但文件没动」

底层就是 `packages/core/` 里那批纯函数（界面 → `lib/host/` 接口层 → `packages/core/`）。
四条主线都能走通：认环境、查改配方、搜装 mod、从零建包、从零装底座、从零加任务/章节、打包导出。

|---|---|

| 体检 | 空标题、断链、缺本地化、图标缺失 |
| 改 | 改任务、加任务、加章节、挪坐标、换图标、改依赖、删任务 |
| 装饰 | 给章节画布加/挪/删装饰图 |

| 能力 | 干什么 |
|---|---|
| 生成脚本 | 生成脚本代码给你看，**不写盘** |
| 沙箱校验 | 在沙箱里**真跑一遍**，报缺物品 / 缺配方 |
| 写盘 | 写盘 + 写完自动复验 + 失败自动回滚 |

### 找 mod、装 mod（联网）

| 能力 | 干什么 |
|---|---|
| 搜 mod | Modrinth 免 key 直接用；CurseForge 需要你自己填 key（没填就只用 Modrinth） |
| 装 mod | 按名字装上：先把依赖闭包算成清单给你看（多少 MB、缺什么前置、同名冲突），你点头才下载 |
| 建包 | 从零建包（拼装）：拿本机一个能启动的实例当模板，拼出新包的版本文件、目录、空任务书 |
| 装底座 | 从零装底座（真下载）：游戏本体 + 资源 + 加载器全从网上下，再跑一次加载器安装器打补丁 |

联网的三条规矩（和 PCL 学的，但更保守）：

- **先搜后问**：只报候选（名字 / 版本 / 体积 / 来源 / 前置），不静默落盘；
- **下载只写 `mods/`**：落到 `.part` 临时文件 → 校验 sha1 → 改名，文件不对就不进包；
- **不问就退**：找不到可装版本、断网、限流，都退回「你自己把 jar 丢进 mods/ 也一样能用」。

### 下载引擎（照 PCL 抄的那套）

下载慢是整合包制作里最劝退的一步：一个包动辄几十个 mod、几百 MB，底座还有几百个
库文件。所以这块是照 PCL 的高速下载机制实现的，代码在 `packages/core/downloader.js`：

- **大文件分段并行**：超过 4 MB 的文件切成 8 MB 一段，最多 8 条连接同时下，
  用随机偏移写盘（`RandomAccess` 同思路），下完按偏移拼回原文件。
  4 MB 以下不分段 —— 多一次 Range 探测往返反而更慢。
- **慢分段自动分裂**：不预设「开几条连接合适」，边下边测。某条连接速度不到其它连接
  中位数（或最快值）的 1/4，就把它的剩余部分一分为二重新排队；有防抖判断，
  线路被源站整体限速时不会让所有分段一起反复重启。
- **全局连接池**：所有下载任务共抢一个额度（默认 64），而不是「每个文件固定几条」。
  同时下几百个小库文件时，吞吐是全局最优的，不会把线路挤死。
- **多文件并行**：装 mod 时最多 4 个文件同时下（每个文件内部还能再分段）。
- **可靠性**：请求 30 秒超时、分段读 15 秒无数据即重试（最多 2 次）、
  单文件校验大小 + sha1 通过才 rename。

实测（本机，2026-10-30）：

| 场景 | 结果 |
|---|---|
| Create 18.2 MB，单连接（对照） | 2.78 秒 / 6.56 MB/s |
| Create 18.2 MB，分段并行 | 2.20 秒 / 8.28 MB/s（3 段） |
| 装 4 个 mod（21.3 MB，多文件并行） | 2.67 秒 / 7.98 MB/s，连接池峰值 6 |
| 16 个 2.2 MB 小文件并发 | 连接池峰值正好卡在额度 8 |

连接数可以用环境变量调：`MCSTUDIO_CONNECTIONS=128`（1–256，默认 64）。

### 从零装底座（选版本向导）

本机没有可抄的实例时，走这条：`packages/core/scaffold.js`。

分工是实测逼出来的：**下载归我们，打补丁归官方安装器**。

- 游戏本体、资源、加载器依赖，全部用上面那套下载引擎下（走镜像，几百 MB 几分钟）；
- NeoForge / Forge 的补丁是 Java 程序（installertools、binarypatcher、jarsplitter），
  纯 JS 复刻不现实，所以把依赖摆好之后让安装器 `--offline` 只跑 processor；
- 安装器的 `--mirror` 参数对库下载**不生效**（实测照样去连 `maven.neoforged.net` 并全部超时），
  所以「先下好再让它离线跑」是唯一可行的路。

地址怎么选：`packages/core/version-manifest.js` 的 `candidateUrlsFor()` 按域名判断 ——
加载器域名走 BMCLAPI 镜像（官方直连超时），Mojang 域名走官方（镜像上资源只有 170 KB/s、
还挂掉近一半，官方 7.3 MB/s）。镜像只映射真有对应路径的那六条，`piston-meta` 不映射
（映射过去只会先白等一轮超时）。

实测（本机，2026-10-30）：1.21.1 + NeoForge 21.1.228，下载 678.9 MB / 136.6 秒（约 5 MB/s）
→ 安装器离线打补丁 28 秒 → 建出来的包 **17.8 秒到主菜单**，零崩溃报告。

### 物品图标（任务书里能看见物品长什么样）

改任务书时最烦的是「`create:cogwheel` 到底是哪个东西」。所以列表、任务详情、加任务表单、
拖拽画布上都直接显示物品图标，代码在 `packages/core/item-icon.js`，全部本机解析、不联网。

怎么找到图的（三轮，越往后越绕）：

1. **直接命中** `assets/<mod>/textures/item/<名字>.png` 或 `textures/block/<名字>.png`；
   名字放在子目录里的（`textures/block/water_wheel/*.png`）按第一段也算；
2. **靠模型反查**：模板里的 `models/item/<名字>.json` 里写 `textures.layer0`，
   顺着 `parent` 链最多往上追 6 层（Create 的物品模型常常只有一行 parent，贴图藏在方块模型里）；
3. **原版物品**：先按 `assets/indexes/<id>.json` 里的 hash 去 `assets/objects/` 拿；
   索引不完整时（实测有的整合包索引里一个贴图键都没有）退回从客户端 jar 里读。

命中率实测（本机「重度机械症」183 个 mod jar、395 个任务）：索引 206 ms、
取 128 个图标 99 ms，**命中 110 个（86%）**，图片原始字节合计 119 KB。
没命中就显示一个字母方块（`C` = cogwheel），不会报错、也不会卡住。

还缺的那 14% 是同一类情况：这些物品用 `.obj` 三维模型（Create 的水车、传动轴），
根本没有一张 2D 图标可拿。`minecraft:` 开头的原版物品也是同理优先找资源索引。

### 高清图标：让游戏自己画（100% 有图）

上一条那 14% 靠自己解析是拿不到的 —— 三维模型的物品，只有游戏自己渲染才画得对。
所以做了一层「叠加」：如果实例里有游戏导出的图标，就优先用它；没有才退回上面的 jar 直读。

怎么生成（一次性，之后一直能用）：

1. 装两个 mod：**Icon Exporter**（Modrinth 工程 `8KCmS7Bd`）+ 前置 **Cyclops Core**（`Z9DM0LJ4`）；
2. 用 PCL 或本软件启动这个包，进游戏 → 单人游戏 → 新建世界；
3. 进世界后按 `T`，打一条命令：`/iconexporter export 64`（64 = 图标边长像素）；
4. 等 1–3 分钟，它会遍历**所有已注册物品**（含 NBT 变体），输出透明底 PNG；
5. 回到软件点「重新扫描图标」，就会看到「图标：游戏导出的高清图 1895 个」。

产物在 `<实例目录>/icon-exports-x64/` 下，文件名是 `<modid>__<itemid>.png`（NBT 变体会多几段），
代码在 `packages/core/icon-export.js`，只读不写、不联网。

实测（本机「最小包」，1.21.1 + NeoForge + Create）：**2150 个 PNG / 3.9 MB**，
其中 1895 个能对上物品 ID（其余是流体和 NBT 变体，流体不是物品所以跳过）。
之前 86% 那个上限被突破了 —— `create:water_wheel`、`create:mechanical_drill`、
`create:fluid_pipe`、`minecraft:copper_ingot` 这些统统有了真图，取图**用时 25 ms**
（完全不读 jar，直接读 PNG 文件）。

导完那两个 jar 可以留着，也可以删掉（纯客户端工具，不参与玩法；删了导出目录里的图还在）。

### 图形化界面

软件界面（`packages/ui/app.js`）现在有这些段：① 连接整合包（含「选择文件夹…」）→ 从零建一个包（抄本机现成底座）→ 从零装一个底座（选版本+加载器，从网上下游戏本体）→ ② 总览 → ③ 装 mod（联网搜、勾选、看要下的清单、确认下载）→ ④ 要下的东西 → ⑤ 找物品 ID → ⑥ 这个物品的配方 → ⑦ 改这条配方 → ⑧ 任务书（每行带物品图标）→ ⑨ 改这条任务 → ⑩ 打包发给别人 → ⑪ 从零加任务 / 加章节（填物品 ID 就显示图标）→ ⑫ 拖拽画布（节点就是物品格子，按住拖、松手暂存、点保存才写盘）。

界面不直接动文件，它走 `lib/host/` 接口层，接口层再调 `packages/core/` 同一批函数 ——
所以「点界面改」和「让模型改」改出来的是同一种结果。

### 让模型来改：内置 MCP 服务器

原来的「模型工具层」被**桌面版内置的 MCP 服务器**取代了。

- 它是一个 **stdio** 形态的 MCP 服务器，跟着软件一起跑；
- **任何 MCP 客户端**都可以把它挂载起来用（不需要非得是某个特定工具）；
- 挂上以后，模型就能调上面那些能力（认实例、查配方、改任务书、跑 KubeJS、装 mod、打包……）；
- 挂载方式和具体参数见软件里的说明。

好处是：模型能做的事，和你在界面上点出来的事，**走的是同一套底层**（`packages/core/`），
不会出现「模型说改好了、文件却没动」这种事。

## 还缺什么

按四条主线列，缺的东西很明确：

### 主线 1：图形化

界面里已经能：

- **连接整合包**：自动扫到 PCL 下载目录、官方启动器、Prism / HMCL 里的包，也能手填路径，还能点「选择文件夹…」直接在弹出的窗口里挑
- **从零建一个包**：本机已经有这个版本的游戏时用这条 —— 挑一个能启动的实例当模板 → 填个名字 → 「算计划」看清单 → 「真建这个包」，几秒钟，建完自动连上
- **从零装一个底座**：本机什么都没有时用这条 —— 填根目录和包名、选游戏版本和加载器 → 「算计划」看要下多少 → 「开始装」，从网上下游戏本体 + 资源 + 加载器（几百 MB，第一次实测 678.9 MB / 136.6 秒 + 打补丁 28 秒；文件都在了再装一次 27 秒），装完自动连上
- **整合包总览**：这个包是什么 MC 版本、什么加载器、多少 mod、多少物品、多少配方
- **联网装 mod**：搜名字 → 勾选 → 「算要下什么」（带依赖、体积、冲突）→ 「真下载」，下完自动刷新 mod 数
- **找物品**：**中英文都能搜**（搜「齿轮」或「cogwheel」都行），点一下复制 ID
- **改配方**：选产物、选材料、填数量，先预览会写什么，再确认写入
- **改任务**：点开一条任务，改标题/描述/要交的东西，先预览再写入；列表、详情、加任务表单、画布上都能看到**物品图标**，一眼认出是哪个物品
- **打包**：选三形态之一（只打内容 / 带游戏本体 / 连启动器一起），看体积和大头目录，点一下真打 zip，带 PCL 兼容自检
- **从零加任务 / 加章节**：新建一章、往章里加任务、指定要交的物品和前置任务，都是先预览再写入
- **拖拽画布**：在图上按住任务节点拖，松手只暂存，点「保存这次挪动」才写盘（写前备份、写完体检、出问题整批回滚）；点一下节点还能**就地改它的标题/副标题/说明**，不用滚回上面找编辑器

剩下的是打磨：

- 任务书还不能拖拽新建连线（现在只能改已有依赖关系）
- 中英双语（现在文案全是中文硬编码）

技术上已经通了：界面 → 宿主接口（`lib/host/api.js`）→ `packages/core/*`。
加新功能就是照这个路子再开一条路由 + 一块界面。

### 主线 3：从零做整合包（已经能从头走到尾）

已经能：

- **选版本 + 加载器装底座**：选 1.21.1 + NeoForge，从 Mojang 和 BMCLAPI 镜像把游戏本体、3911 个资源、加载器依赖全下下来，再跑一次官方安装器打补丁 → 建出来的包直接能启动（实测 17.8 秒到主菜单）
- **建骨架（不下载的快速路）**：拿本机一个能启动的实例当模板，抄版本文件 + 客户端 jar + libraries，配上空 `mods/`、`kubejs/`、空任务书 → 建出来的包直接能启动（实测 17.2 秒到主菜单）

- **建空任务书**：`config/ftbquests/quests/` 的 `data.snbt` 已经生成
- **从零加章节 / 加任务**：界面和模型都能做，写盘前自动备份，写坏了整批回滚
- **拖拽画布**：界面上按住节点拖，模型侧也能干同一件事，两边共用 `packages/core/quest-move.js`
- **打包导出**：三形态，带 PCL 兼容自检

## 怎么用

### 方式一：点界面

1. 启动软件（桌面上那个图标，或双击 `启动.cmd`）；
2. 界面会自动扫到你机器上 PCL 下载目录里的整合包，点一个就连上；记不住路径就点「选择文件夹…」，在弹出的窗口里挑；
3. 上面显示这个包的版本、加载器、多少 mod、多少物品和配方；
4. 下面搜索框可以找物品，**中文英文都行**，搜到了点一下复制 ID。

### 方式二：说人话

把软件内置的 MCP 服务器挂到你的 MCP 客户端上，然后直接说：

> **你**：帮我看看 `D:\pcl2\PCL 下载\整合包\重度机械症\versions\Mechanomania` 这个包
>
> **它**：告诉你这是 NeoForge 1.21.1，183 个 mod，Java 21。

> **你**：机械动力的齿轮现在怎么合成？
>

## 安全边界

这几条是硬约束，界面做出来以后同样适用：

- **默认只读**。所有写操作都是 **先给方案（不写盘）→ 你确认 → 才写盘**。
- **写盘前自动备份**，失败自动回滚。
- **不动你的存档**，不改存档名，不删文件。
- **不偷偷联网下载 mod**。

## 已知限制

- **ZIP64 不支持**（MC 的 jar 都远小于 4 GB，暂时够用）。
- **联网只做 Modrinth**。CurseForge 要你自己填 API key（`MCSTUDIO_CURSEFORGE_KEY`），没填就只用 Modrinth。
- **联网默认走官方源**，被墙/限流时可设 `MCSTUDIO_MIRROR=prefer` 走镜像（PCL 同款 mcimirror）。
- **下载并发默认 64 条连接**，线路很好可以设 `MCSTUDIO_CONNECTIONS=128`（1–256），线路差就调小。
- **从零装底座要联网**：游戏本体和资源走 Mojang 官方，加载器依赖走 BMCLAPI 镜像（`maven.neoforged.net` 直连会超时）。断网就退回「抄本机现成实例」。
- **从零装底座靠官方安装器打补丁**：NeoForge/Forge 的 processor 是 Java 程序，我们不重写它，而是先把依赖全下好再让安装器 `--offline` 跑一遍 —— 所以这一步必须有 Java。
- **Fabric / Quilt 还不能从零装**：它们没有这种安装器，走的是另一套流程，还没做。
- **1.20 与 1.21 的格式差异**已兼容，更老的版本没测过。NeoForge 的 1.20.1 及更早没有正式版，选版本时会明确拒绝。
- **`ftb-quests` 本体在 Modrinth 上没有**（只有 addon），要装得填 CurseForge key 或手动把 jar 放进 `mods/`。
- **物品图标**：不导也能用（约 86% 有图，`.obj` 三维模型的物品会显示成字母方块）；想要 100% 得先在游戏里跑一次 `/iconexporter export 64`，见上面「高清图标」那节。
- **图标索引是懒建的**：第一次打开任务书会多花约 0.2–0.4 秒扫 mod jar，之后 10 分钟内走缓存；有导出目录时反而更快（直接读 PNG，实测 25 ms）。
- **启动验证要在沙箱外跑**。受限沙箱里 `spawn` 会被拒（`spawn EPERM`），得放开权限才行。
- **GPU 硬件加速不兼容的机器要跑安全模式**：启动.cmd 里有三级降级链（裸跑 → `--safe-mode --no-sandbox` → `--single-process`），实在起不来会自动降一级。
